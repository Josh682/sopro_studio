├── docs/                      # Documentation folder
│   └── Foundation/            # Core architectural and structural design documents
├── src/                       # Application source code
│   ├── gui/                   # GUI Layer (PyQt6)
│   │   ├── __init__.py
│   │   ├── main_window.py     # QMainWindow, sidebar, QStackedWidget for navigation
│   │   ├── styles.py          # Catppuccin Mocha stylesheet constants

## Naming Conventions

- **Files and Directories:** Use `snake_case` (e.g., `main_window.py`, `stem_separator.py`).
- **Classes:** Use `PascalCase` (e.g., `MainWindow`, `BaseProcessor`, `StemSeparatorWorker`).
- **Functions and Variables:** Use `snake_case` (e.g., `process_audio`, `file_path`).
- **Constants:** Use `UPPER_SNAKE_CASE` (e.g., `MAX_THREADS`, `SAMPLE_RATE`).

## Extending the Application

### Adding a New Processor
1. Create a new file in `src/core/processors/` (e.g., `noise_reducer.py`).
2. Define a class that inherits from `BaseProcessor` (e.g., `NoiseReducerProcessor`).
3. Implement the required `process()` method.
4. Register the new processor in `src/core/processor_registry.py`.

### Adding a New AI Model
1. Create a wrapper script in `src/ai/models/` (e.g., `denoiser_model.py`).
2. Implement model loading, MPS configuration, and inference logic.
3. Ensure the model downloads its weights into the `models/` directory automatically if not present.
4. Consume this wrapper within a relevant processor in `src/core/processors/`.

### Adding a New Feature Page
1. Create a new UI file in `src/gui/pages/` (e.g., `noise_reduction_page.py`).
2. Design the layout and inputs using reusable components from `src/gui/widgets/`.
3. Connect the UI inputs to a `ProcessorWorker` configured with your new processor.
4. Import and add the page to the `QStackedWidget` inside `src/gui/main_window.py`.
5. Add a corresponding navigation button to the sidebar.

## Git Ignore Policies

To keep the repository clean and efficient, the following items are included in `.gitignore`:
- `models/`: AI model weights are often massive (GBs) and should be downloaded dynamically or provided separately.
- `logs/`: Runtime logs are specific to the user's local execution.
- `output/`: Processed audio files generated by the user.
- `__pycache__/`, `*.pyc`: Compiled Python bytecode.
- `.venv/`: Local Python virtual environments.
- `.DS_Store`: macOS system directory settings.

## Import Path Conventions

Always use absolute imports starting from the `src` root to prevent relative import hell and ambiguity.

**Correct:**
```python
from src.core.processors.format_converter import FormatConverter
from src.utils.logger import get_logger
```

**Incorrect:**
```python
from ..core.processors.format_converter import FormatConverter
import utils.logger
```
